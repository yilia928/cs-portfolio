RAG 问答机器人评估报告

评估对象：云帆ERP智能客服 RAG（离线混合检索 + 抽取式回答；配置大模型 API Key 后生成层切换为 LLM，检索链路不变）
测试集：100 题（项目③ VoC 真实客户提问 60 题 + 人工跨模块补充 40 题），覆盖 15 个帮助模块
评估日期：2025-09（本地离线可复现，python tests/eval_rag.py）

1. 评估指标与方法

指标 定义
Recall@K Top-K 召回块中是否包含期望模块（检索能不能找到正确资料）
MRR 第一个正确模块块的倒数排名（正确资料排得靠不靠前）
模块精度 ModPrec@K Top-K 中属于期望模块的块占比（引用正确率的代理：噪声块越少，LLM 被干扰越少）
转人工率 Handoff Top1 相似度低于置信阈值而兜底转人工的比例
答案关键词覆盖率 抽取式答案命中该题期望关键词的比例（40 道人工题人工标注关键词）

检索方案为词级 TF-IDF（1-2gram，叠加低权重同义词扩展）+ 字符 ngram（char_wb 2-3gram）混合余弦，
并对多字符实词的标题命中加权。字符 ngram 解决错字、英文/中文混写与未登录词；
同义词扩展解决客户口语与文档术语不一致（如“不回传”→“回传失败/批量补传”）。

2. 一次真实修复：默认示例问题离线答不出

现场演示的第一题“物流单号一直不回传怎么办？”在初版离线模式下错误转人工，拆解为两个独立断点：

  1. 检索：含“五步排查”原文的块排第二（0.0983），“跟踪号管理与换号”块靠标题词面命中排第一；
  2. 抽取：排查句（“回传失败进入重试队列，前3次间隔15分钟”）不重复提问原词，词覆盖率最高仅 0.33，
    被 0.34 的硬阈值全部砍掉，抽取结果为空 → 触发兜底。

修复（评估驱动，非拍脑袋）：

  • 查询扩展：建立约 40 条“客服口语→文档术语”短语表（词条归纳自项目③真实提问），
    在原文上做子串匹配，扩展词以 0.5 低权重只注入词级 TF-IDF 向量，避免带偏召回；
  • 抽取阈值配置化：词覆盖门槛 0.34→0.25（常量 EXTRACT_COVER_THRESHOLD），
    覆盖率只计多字符实词并把扩展词计入；每个召回块最多贡献 2 句；切句不再在“；”断开，保留完整排查序列。

修复后该题离线回答包含完整排查顺序与“重新回传/批量补传”操作路径，且全部句末带来源编号。

3. 消融实验：查询扩展到底有没有用

在选定配置（标准切块 / 词权重 0.6 / TopK=5）上做开关对比：

查询扩展 Recall@5 MRR 模块精度 转人工率 答案关键词覆盖 答案产出率
关 0.97 0.8725 0.538 0.06 0.8289 0.95
开（选定） 0.97 0.8938 0.558 0.05 0.859 0.975

扩展开启后 MRR 提升约 2 个点、模块精度提升 2 个点，答案关键词覆盖从 0.83 提升到 0.86，
答案产出率（curated 40 题中成功组织出答案的比例）从 0.95 提升到 0.975，且 Recall 与转人工率无劣化。
扩展词表同时修复了“订单量超了套餐额度怎么办”等口语问法（能答出超额计费规则原文）。

实验结论（每一步调参的取舍）

  1. 切块大小：标准 200-500 字（模块级贪心打包）优于约 240 字小窗口。 小窗口把同小节的上下文拆散，
    排查步骤类内容被分到两个块，Recall 低 2 个点；模块级打包还让相邻小节（跟踪号→回传失败）共处一块，
    反而对“单号不回传”这类跨小节问题友好。
  2. TopK：选定 K=5。 K=3 模块精度更高，但漏掉正确块的概率增加约 3 个百分点；K=5 以可接受的精度损失换召回，
    再由生成层 prompt 约束只依据资料作答、引用编号，控制噪声影响。
  3. 词权重选定 0.6 / 字符 0.4：纯词面匹配对错字与英文报错码不够鲁棒，纯字符又会引入同形噪声；0.6 为网格最稳区间。
  4. 置信阈值 0.11 保持不动：扩展后域内最低分问题（“新手第一次用先学哪几个模块”，0.098）与
    最像业务问题的越界提问（“推荐几本科幻小说”，0.092）之间仅有 0.006 的余量，
    为单题压低阈值会让兜底失去保护——宁可对这 1/40 题安全转人工，不冒误导风险。

5. 最终效果

  • Recall@5 = 0.97，MRR = 0.8938，模块精度 = 0.558；
  • 抽取式答案关键词覆盖 = 0.859，答案产出率 = 0.975；
  • 40 道人工题中错误转人工 1 题（安全失败）；越界问题（老板是谁、天气、写诗、查余额）全部正确兜底；
  • 修复后的默认示例问题可离线给出完整排查步骤与操作入口，断网环境演示链路完整。

6. 已知局限与下一步

  1. 长且口语化的问题（“新手第一次用先学哪几个模块”）被通用词拉低余弦分，处于阈值下方；下一步可对问题先做停用词压缩或用 embedding 语义检索；
  2. 同义词表靠人工维护（约 40 条），扩词来源应持续接入项目③的新提问；接入 embedding 后可用“未命中问题挖掘”自动发现新词；
  3. 生成质量在配置 LLM API Key 后应重新评估：答案正确性需人工逐条标注（当前抽取式用关键词覆盖率代理）；
  4. 测试集期望标签是“模块级”，未来可升级到“文章级/块级”标注，做更严格的引用正确率。
